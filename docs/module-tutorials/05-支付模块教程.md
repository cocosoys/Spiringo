# 支付模块教程

支付模块通过统一 `Channel` 接口接入微信、支付宝、银联、云闪付、数字人民币、Stripe 和 PayPal，提供创建支付、回调、退款、查询和关闭订单能力。

## 1. 复制代码

复制模块代码：

```text
internal/modules/payment/
  payment.go
  migrations.go
  dto/
  model/
  repository/
  service/
  handler/
  channel/
```

同时复制基础设施：

```text
internal/modules/tenant/
internal/core/event/
internal/core/module/
internal/pkg/orm/
pkg/types/
```

支付模块依赖租户模块做数据隔离，支付成功/失败/退款/关闭会发布事件。

## 3. 启用配置

基础配置：

```yaml
modules:
  payment:
    enabled: true
    default_notify_url: "https://api.example.com/api/v1/payment/callback/wechat"
    wechat:
      enabled: false
      app_id: ""
      mch_id: ""
      api_v3_key: ""
      api_key: ""
      serial_no: ""
      private_key: ""
      cert_path: ""
    alipay:
      enabled: false
      app_id: ""
      private_key: ""
      is_prod: false
      app_cert_path: ""
      alipay_cert_path: ""
      root_cert_path: ""
    stripe:
      enabled: false
      secret_key: ""
      webhook_secret: ""
    paypal:
      enabled: false
      client_id: ""
      client_secret: ""
      sandbox: true
      webhook_id: ""
```

生产要求：

- 所有网关密钥从安全配置系统或环境变量注入，不要提交到仓库。
- `default_notify_url` 必须是公网可访问地址。
- 支付宝证书路径如果任一项填写，必须同时提供 app、alipay、root 三个证书。
- PayPal 的 `sandbox` 在生产环境应设为 `false`。

## 6. HTTP 接口

路由前缀：

```text
/api/v1/payment
```

接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/payment/create` | 创建支付订单 |
| `POST` | `/api/v1/payment/callback/:channel` | 接收支付网关回调 |
| `POST` | `/api/v1/payment/refund` | 发起退款 |
| `GET` | `/api/v1/payment/query/:id` | 查询本地订单 |
| `POST` | `/api/v1/payment/close/:id` | 关闭订单 |

创建支付请求：

```json
{
  "out_trade_no": "ORDER202605080001",
  "amount": 9900,
  "currency": "CNY",
  "subject": "专业版订阅",
  "channel": "wechat",
  "scene": "native",
  "notify_url": "https://api.example.com/api/v1/payment/callback/wechat",
  "return_url": "https://example.com/pay/return",
  "open_id": ""
}
```

字段限制：

| 字段 | 说明 |
| --- | --- |
| `amount` | 整数金额，通常按分保存 |
| `channel` | `wechat`, `alipay`, `unionpay`, `cloudpay`, `digital_rmb`, `stripe`, `paypal` |
| `scene` | `jsapi`, `app`, `h5`, `native`, `qrcode` |
| `out_trade_no` | 商户订单号，必须全局唯一 |

退款请求：

```json
{
  "out_trade_no": "ORDER202605080001",
  "out_refund_no": "REFUND202605080001",
  "total_amount": 9900,
  "refund_amount": 9900,
  "reason": "用户申请退款"
}
```

## 7. 回调处理

支付网关回调地址格式：

```text
POST /api/v1/payment/callback/<channel>
```

例如：

```text
POST /api/v1/payment/callback/wechat
POST /api/v1/payment/callback/alipay
POST /api/v1/payment/callback/stripe
```

模块会读取原始 body：

```go
body, err := io.ReadAll(c.Request.Body)
```

然后交给通道验证签名、解析状态并更新订单。回调响应由通道的 `CallbackSuccess` 或 `CallbackFail` 决定，避免强制所有网关返回同一种 JSON。

## 8. 事件应用

支付模块会发布：

```text
payment.created
payment.success
payment.failed
payment.refunded
payment.closed
payment.fulfillment_requested
```

典型应用：

- 通知模块订阅 `payment.success` 和 `payment.failed` 发送通知。
- 订单模块订阅 `payment.fulfillment_requested` 开通权益。
- 财务模块订阅 `payment.refunded` 做退款对账。

## 9. 新增支付通道

新增文件：

```text
internal/modules/payment/channel/bankpay.go
```

实现统一接口：

```go
type Channel interface {
    Name() string
    CreateOrder(ctx context.Context, order OrderRequest) (*OrderResponse, error)
    HandleCallback(ctx context.Context, req *http.Request, body []byte) (*CallbackResult, error)
    Refund(ctx context.Context, req RefundRequest) (*RefundResponse, error)
    Query(ctx context.Context, outTradeNo string) (*QueryResponse, error)
    Close(ctx context.Context, outTradeNo string) error
    CallbackSuccess() any
    CallbackFail() any
}
```

在 `payment.go` 的 `Init()` 中按配置注册：

```go
if m.config.BankPay.Enabled {
    chReg.Register(channel.NewBankPayChannel(...))
}
```

## 10. 常见问题

- 创建支付返回通道不存在：检查对应通道 `enabled` 是否为 `true`，并确认已在 registry 注册。
- 回调一直失败：检查网关签名密钥、证书、公网回调地址和原始 body 读取逻辑。
- 支付成功但业务未开通：检查是否订阅了 `payment.fulfillment_requested`。
- 多租户订单串租户：确认请求携带 `X-Tenant-ID`，repository 使用 `TenantDB`。
