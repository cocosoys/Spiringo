# 通知模块教程

通知模块支持 Webhook、Email 和站内信 inbox。它既可以通过 HTTP 主动发送通知，也可以订阅支付、租户等事件自动生成通知。

## 1. 复制代码

复制模块代码：

```text
internal/modules/notification/
  notification.go
  subscriptions.go
  dto/
  model/
  repository/
  service/
  handler/
```

同时复制基础设施：

```text
internal/core/event/
internal/core/module/
internal/pkg/orm/
pkg/types/
```

如果要订阅支付或租户事件，还需要复制对应事件定义和发布方模块：

```text
internal/core/event/events.go
internal/modules/payment/
internal/modules/tenant/
```

## 2. 复制依赖

通知模块主要使用标准库和基础 Web/ORM 依赖：

```bash
go get github.com/gin-gonic/gin
go get github.com/google/uuid
go get gorm.io/gorm
```

Webhook 使用 `net/http`，Email 使用 `net/smtp`，不需要额外第三方包。

## 3. 启用配置

当前默认配置中通知模块是关闭的，需要手动开启：

```yaml
modules:
  notification:
    enabled: true
    events:
      - "payment.failed"
      - "payment.success"
      - "tenant.suspended"
    webhook:
      enabled: false
      urls: []
      timeout: "5s"
      headers: {}
    email:
      enabled: false
      host: ""
      port: 587
      username: ""
      password: ""
      from: ""
      to: []
    inbox:
      enabled: true
```

推荐先启用 `inbox`，确认站内信可用后再接入 Webhook 和 Email。

## 4. 注册模块

通知模块没有强制业务依赖，可以单独注册：

```go
application.RegisterModules(
    notification.NewNotificationModule(),
)
```

如果要接收支付和租户事件，注册发布事件的模块：

```go
application.RegisterModules(
    tenant.NewTenantModule(),
    payment.NewPaymentModule(),
    notification.NewNotificationModule(),
)
```

## 6. HTTP 接口

路由前缀：

```text
/api/v1/notification
```

接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/notification/send` | 主动发送通知 |
| `GET` | `/api/v1/notification/inbox` | 分页查询站内信 |
| `PUT` | `/api/v1/notification/inbox/:id/read` | 标记站内信已读 |

主动发送请求：

```json
{
  "event": "custom.notice",
  "severity": "info",
  "subject": "系统通知",
  "content": "你的申请已经通过。",
  "tenant_id": "tenant-id",
  "recipient_id": "user-id",
  "payload": {
    "source": "manual"
  }
}
```

`severity` 支持：

```text
info, warning, error, critical
```

查询 inbox：

```text
GET /api/v1/notification/inbox?page=1&page_size=20&recipient_id=user-id&unread_only=true
```

标记已读：

```text
PUT /api/v1/notification/inbox/<message-id>/read?recipient_id=user-id
```

## 7. 事件订阅

通知模块当前订阅：

```text
payment.failed
payment.success
tenant.suspended
```

处理逻辑：

- `payment.failed` 生成 error 级别通知。
- `payment.success` 生成 info 级别通知。
- `tenant.suspended` 生成 warning 级别通知。

如果要订阅更多事件，在 `subscriptions.go` 中添加：

```go
func (m *Module) Subscriptions() []module.EventSubscription {
    return []module.EventSubscription{
        {
            Topic:   event.EventPaymentSuccess,
            Handler: m.handlePaymentSuccess,
        },
        {
            Topic:   "order.created",
            Handler: m.handleOrderCreated,
        },
    }
}
```

新增处理函数：

```go
func (m *Module) handleOrderCreated(ctx context.Context, e *event.Event) error {
    return m.svc.Notify(ctx, service.Message{
        Event:    "order.created",
        Severity: "info",
        Subject:  "订单已创建",
        Content:  "你的订单已创建，请及时支付。",
    })
}
```

## 8. Webhook 接入

启用 Webhook：

```yaml
modules:
  notification:
    webhook:
      enabled: true
      urls:
        - "https://example.com/webhook"
      timeout: "5s"
      headers:
        X-Notify-Token: "<token>"
```

应用建议：

- Webhook 地址必须使用 HTTPS。
- 接收方应校验自定义 token 或签名。
- 失败重试策略可在 service 层继续扩展。

## 9. Email 接入

启用 Email：

```yaml
modules:
  notification:
    email:
      enabled: true
      host: "smtp.example.com"
      port: 587
      username: "notice@example.com"
      password: "<smtp password>"
      from: "notice@example.com"
      to:
        - "admin@example.com"
```

生产建议：

- 使用专用 SMTP 凭据。
- 密码从环境变量或配置中心注入。
- 重要告警同时开启 Webhook 和 Email。

## 10. 站内信应用

站内信开启：

```yaml
modules:
  notification:
    inbox:
      enabled: true
```

适用场景：

- 支付成功/失败消息。
- 租户状态变更提醒。
- 审批结果通知。
- 系统公告。

如果消息是面向租户管理员，建议写入 `tenant_id`；如果消息是面向具体用户，写入 `recipient_id`。

## 11. 常见问题

- 没有站内信：检查 `modules.notification.enabled` 和 `modules.notification.inbox.enabled` 是否都为 `true`。
- 支付成功没有通知：检查支付模块是否发布 `payment.success`，通知模块是否已注册并订阅。
- Webhook 没有收到：检查 URL、timeout、网络和接收方响应状态。
- Email 发送失败：检查 SMTP host、port、账号密码、TLS 策略和发件人白名单。
