# 认证模块教程

认证模块提供账号注册、登录、登出、刷新令牌、JWT 签发、OAuth 登录和令牌缓存/失效能力。

## 1. 复制代码

复制模块代码：

```text
internal/modules/auth/
  auth.go
  migrations.go
  dto/
  model/
  repository/
  service/
  handler/
  oauth/
```

必须同时复制或实现：

```text
internal/modules/user/
internal/modules/tenant/
internal/core/di/
internal/core/event/
internal/pkg/cache/
internal/pkg/orm/
pkg/types/
```

认证模块依赖用户模块提供的 `auth_user_service`，否则登录和注册只能运行在降级或不可用状态。

## 2. 复制依赖

认证模块需要：

```bash
go get github.com/gin-gonic/gin

```

如启用 Redis 缓存黑名单或刷新令牌缓存，还需要：

```bash

```

## 3. 启用配置

基础配置：

```yaml
modules:
  auth:
    enabled: true
    jwt:
      secret: "change-me-in-production"
      access_expire: "2h"
      refresh_expire: "168h"
      issuer: "spiringo"
    oauth:
      wechat:
        enabled: false
        app_id: ""
        app_secret: ""
      google:
        enabled: false
        client_id: ""
        client_secret: ""
```

生产要求：

- `jwt.secret` 必须替换为高强度密钥。
- `access_expire` 保持较短，例如 `15m` 到 `2h`。
- `refresh_expire` 可保持较长，例如 `168h`。
- OAuth 回调地址必须和第三方平台后台配置一致。

## 4. 注册模块

认证模块依赖用户和租户：

```go
application.RegisterModules(
    tenant.NewTenantModule(),
    user.NewUserModule(),
    auth.NewAuthModule(),

```

模块依赖声明：

```go
module.NewBaseModule("auth", "user", "tenant")
```

## 6. HTTP 接口

路由前缀：

```text
/api/v1/auth
```

接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/auth/login` | 账号密码登录 |
| `POST` | `/api/v1/auth/register` | 注册并返回令牌 |
| `POST` | `/api/v1/auth/logout` | 登出并失效当前令牌 |
| `POST` | `/api/v1/auth/refresh` | 使用刷新令牌换取新访问令牌 |
| `GET` | `/api/v1/auth/oauth/:provider` | 跳转第三方授权页 |
| `GET` | `/api/v1/auth/oauth/:provider/callback` | 第三方回调换取本系统令牌 |

登录请求：

```json
{
  "username": "alice",
  "password": "secret123"
}
```

注册请求：

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "phone": "13800000000",
  "password": "secret123",
  "nickname": "Alice"
}
```

刷新请求：

```json
{
  "refresh_token": "<refresh token>"
}
```

认证请求头：

```text
Authorization: Bearer <access token>
```

## 7. OAuth Provider 接入

内置 Provider：

```text
wechat, qq, google, discord, telegram, x, dingtalk, douyin, work_wechat
```

Provider 统一实现：

```go
Name()
AuthURL()
GetUser()
RefreshToken()
```

启用 Google 示例：

```yaml
modules:
  auth:
    oauth:
      google:
        enabled: true
        client_id: "<client id>"
        client_secret: "<client secret>"
        redirect_url: "https://api.example.com/api/v1/auth/oauth/google/callback"
```

授权入口：

```text
GET /api/v1/auth/oauth/google?redirect_url=https://api.example.com/api/v1/auth/oauth/google/callback
```

需要严格校验回调地址的平台，应在登录和回调阶段传入同一个 `redirect_url`。

## 8. 与中间件集成

全局认证中间件配置位于：

```yaml
middleware:
  auth:
    enabled: false
    jwt_secret: ""
    public_paths:
      - "/api/v1/auth/login"
      - "/api/v1/auth/register"
      - "/api/v1/auth/refresh"
      - "/api/v1/auth/oauth/*"
```

如果要启用全局 JWT 中间件：

```yaml
middleware:
  auth:
    enabled: true
    jwt_secret: "same-as-modules-auth-jwt-secret"
```

保持 `jwt_secret` 与 `modules.auth.jwt.secret` 一致。

## 9. 事件应用

认证模块会使用认证事件载荷，适合扩展：

```text
auth.login
auth.logout
auth.oauth_bound
```

可用于：

- 登录审计。
- 异常登录通知。
- OAuth 账号绑定通知。
- 安全风控。

## 10. 常见问题

- `rbac` 初始化失败：检查 `auth` 模块是否启用，因为 RBAC 需要 `AuthService` 作为 token validator。
- 登录后访问受保护接口失败：检查请求头是否为 `Authorization: Bearer <token>`。
- OAuth 回调失败：检查 provider 名称、第三方后台回调地址和 `redirect_url` 是否一致。
- 登出后令牌仍可用：检查缓存实现是否启用；内存缓存只适合单进程开发环境。
