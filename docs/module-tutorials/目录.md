# Spiringo 模块化教程目录

本目录汇总当前项目已经完成并接入的模块化能力。教程面向两类使用方式：

- 在本项目中启用、配置和调用已有模块。
- 把某个模块复制到另一个 Spiringo 风格项目中复用，并补齐依赖、配置、注册和迁移。

## 当前已完成模块清单

当前内置模块由 `internal/modules/builtin/builtin.go` 统一注册，顺序为：

```go
application.RegisterModules(
    tenant.NewTenantModule(),
    user.NewUserModule(),
    auth.NewAuthModule(),
    rbac.NewRBACModule(),
    payment.NewPaymentModule(),
    qrcode.NewQRCodeModule(),
    notification.NewNotificationModule(),
)
```

这些模块会由框架按依赖拓扑排序初始化。实际依赖关系如下：

| 模块 | 依赖模块 | 路由前缀 | 默认是否启用 |
| --- | --- | --- | --- |
| `tenant` | 无 | `/api/v1/tenant` | 是 |
| `user` | `tenant` | `/api/v1/user` | 是 |
| `auth` | `user`, `tenant` | `/api/v1/auth` | 是 |
| `rbac` | `auth`, `user`, `tenant` | `/api/v1/rbac` | 是 |
| `payment` | `tenant` | `/api/v1/payment` | 是 |
| `qrcode` | `tenant` | `/api/v1/qrcode` | 是 |
| `notification` | 无 | `/api/v1/notification` | 默认配置关闭，需要手动启用 |

## 最小落地流程

1. 复制通用框架目录，见 [模块化框架接入教程](00-模块化框架接入教程.md)。
2. 复制目标模块目录，例如 `internal/modules/payment`。
3. 确认 `go.mod` 中存在教程列出的依赖。
4. 在 `configs/config.yaml` 的 `modules.<name>` 下启用模块并填入真实配置。
5. 在 `internal/modules/builtin/builtin.go` 或你的应用入口中注册模块。
6. 执行迁移：

```powershell
$env:GOARCH='amd64'
$env:CGO_ENABLED='1'
go run ./cmd/spiringo migrate up -env development -config configs
```

7. 启动服务：

```powershell
go run ./cmd/spiringo -env development -config configs
```

8. 访问 `GET /system/report.json` 查看模块是否处于 `active` 状态。

## 复制模块时的边界

- 只复制单个业务模块还不够，模块依赖 `internal/core/module`、`internal/core/app`、`internal/core/di`、`internal/core/event`、`internal/pkg/orm` 和 `pkg/types` 等基础设施。
- 若复制 `auth`，必须同时复制或实现用户服务接口，因为认证模块通过 `auth_user_service` 命名依赖读取用户能力。
- 若复制 `rbac` 并保持 `auth_required: true`，必须先接入 `auth` 模块，因为路由会使用 JWT 校验器。
- 若复制 `qrcode` 并希望保存图片到对象存储，需要同时接入 `internal/pkg/storage`；未启用对象存储时仍可直接返回 PNG 二进制。
- 若复制 `payment`，第三方网关凭据必须来自真实商户后台；演示配置只适合本地开发。
- 若复制 `notification`，站内信可独立运行，Webhook 和 Email 需要真实外部服务配置。
