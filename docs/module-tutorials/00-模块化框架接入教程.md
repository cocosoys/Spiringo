# 模块化框架接入教程

本教程说明如何把 Spiringo 的模块化单体框架复制到新项目，或在当前项目中新增、启用、注册一个模块。

## 1. 复制基础代码

如果是从当前项目复制到另一个项目，至少复制这些目录：

```text
cmd/spiringo/
configs/
internal/core/app/
internal/core/config/
internal/core/di/
internal/core/event/
internal/core/middleware/
internal/core/migrate/
internal/core/module/
internal/core/server/
internal/pkg/orm/
internal/pkg/cache/
internal/pkg/logger/
internal/pkg/metrics/
internal/pkg/queue/
internal/pkg/storage/
internal/pkg/trace/
pkg/types/
pkg/constants/
```

只使用最小模块时，`storage`、`metrics`、`queue`、`trace` 等可以按需裁剪；但如果直接复用当前业务模块，建议先完整复制，确认运行后再精简。

## 2. 复制依赖

基础框架至少需要：

```bash
go get github.com/gin-gonic/gin
go get github.com/spf13/viper
go get github.com/fsnotify/fsnotify
go get gorm.io/gorm
go get gorm.io/driver/mysql
go get gorm.io/driver/postgres
go get gorm.io/driver/sqlite
go get github.com/redis/go-redis/v9
go get github.com/google/uuid
```

如果完整复制当前项目，直接复用根目录的 `go.mod` 更稳妥，然后执行：

```powershell
go mod tidy
```

Windows 下如果启用 SQLite 或任何 CGO 相关依赖，建议显式指定：

```powershell
$env:GOARCH='amd64'
$env:CGO_ENABLED='1'
$env:GOCACHE=(Join-Path (Get-Location) '.cache\go-build')
```

## 3. 理解模块接口

所有模块都实现 `internal/core/module.Module`：

```go
type Module interface {
    Name() string
    Dependencies() []string
    Config() any
    Init(app *App) error
    Start(ctx context.Context) error
    Stop(ctx context.Context) error
    State() ModuleState
}
```

常用可选接口：

```go
type Routable interface {
    Routes(r *gin.RouterGroup)
}

type Migratable interface {
    Migrations() []Migration
}

type EventSubscriber interface {
    Subscriptions() []EventSubscription
}
```

框架会自动完成以下流程：

1. 按 `Dependencies()` 拓扑排序。
2. 检查 `modules.<name>.enabled` 是否启用。
3. 将 `modules.<name>` 绑定到 `Config()` 返回的结构体。
4. 调用 `Init()`。
5. 如实现 `Routes()`，挂载到 `/api/v1/<name>`。
6. 如实现 `Subscriptions()`，订阅事件总线。
7. 如实现 `Migrations()`，执行模块迁移。
8. 调用 `Start()`。

## 4. 新增模块骨架

创建目录：

```text
internal/modules/order/
  order.go
  migrations.go
  dto/
  model/
  repository/
  service/
  handler/
```

最小模块代码：

```go
package order

import (
    "context"
    "fmt"

    "github.com/gin-gonic/gin"
    "github.com/spiringo/spiringo/internal/core/module"
)

type Config struct {
    EnabledFeature bool `yaml:"enabled_feature" mapstructure:"enabled_feature"`
}

type OrderModule struct {
    *module.BaseModule
    config Config
}

func NewOrderModule() *OrderModule {
    return &OrderModule{
        BaseModule: module.NewBaseModule("order", "tenant"),
    }
}

func (m *OrderModule) Config() any {
    return &m.config
}

func (m *OrderModule) Init(app *module.App) error {
    if app == nil {
        return fmt.Errorf("order app is nil")
    }
    return nil
}

func (m *OrderModule) Routes(r *gin.RouterGroup) {
    r.GET("/ping", func(c *gin.Context) {
        c.JSON(200, gin.H{"module": "order", "ok": true})
    })
}

func (m *OrderModule) Start(ctx context.Context) error {
    if ctx != nil {
        return ctx.Err()
    }
    return nil
}

func (m *OrderModule) Stop(ctx context.Context) error {
    if ctx != nil {
        return ctx.Err()
    }
    return nil
}
```

## 5. 注册模块

在 `internal/modules/builtin/builtin.go` 中加入 import 和注册项：

```go
import (
    "github.com/spiringo/spiringo/internal/modules/order"
)

func RegisterAll(application *app.App) {
    application.RegisterModules(
        tenant.NewTenantModule(),
        order.NewOrderModule(),
    )
}
```

如果模块依赖 `tenant`，注册顺序不必手工排序，框架会根据 `Dependencies()` 排序；但人类阅读时仍建议把基础模块写在前面。

## 6. 添加配置

在 `configs/config.yaml` 中添加：

```yaml
modules:
  order:
    enabled: true
    enabled_feature: true
```

关闭模块时：

```yaml
modules:
  order:
    enabled: false
```

关闭依赖模块后，依赖它的模块会被跳过，并在运行报告中显示为 skipped。

## 7. 添加迁移

如果模块需要数据表，实现 `Migrations()`：

```go
func (m *OrderModule) Migrations() []module.Migration {
    return []module.Migration{
        {
            ID: "order_001_create_orders_table",
            Up: func(ctx context.Context) error {
                return m.db.AutoMigrate(&model.Order{})
            },
            Down: func(ctx context.Context) error {
                return m.db.DB().Migrator().DropTable(&model.Order{})
            },
        },
    }
}
```

迁移 ID 要稳定且全局可读，推荐格式：

```text
<module>_<序号>_<动作>
```

例如：

```text
payment_001_create_orders_tables
notification_001_create_messages_table
```

## 8. 使用 DI 传递跨模块依赖

普通依赖：

```go
app.DI.Provide(m.svc)
```

读取普通依赖：

```go
svc, err := di.Resolve[*service.AuthService](app.DI)
```

命名依赖：

```go
app.DI.ProvideNamed("auth_user_service", userService)
```

读取命名依赖：

```go
userSvc, err := di.ResolveNamed[service.UserServiceInterface](app.DI, "auth_user_service")
```

当前项目的用户模块就是通过 `auth_user_service` 向认证模块暴露用户查询和创建能力。

## 9. 使用事件总线解耦模块

发布事件：

```go
app.EventBus.Publish(ctx, event.NewEvent(event.EventPaymentSuccess, payload))
```

订阅事件：

```go
func (m *Module) Subscriptions() []module.EventSubscription {
    return []module.EventSubscription{
        {
            Topic:   event.EventPaymentSuccess,
            Handler: m.handlePaymentSuccess,
        },
    }
}
```

适用场景：

- 支付成功后通知模块发送站内信。
- 租户创建后用户模块创建默认管理员。
- 用户变更后审计模块记录日志。

## 10. 运行和验证

执行迁移：

```powershell
$env:GOARCH='amd64'
$env:CGO_ENABLED='1'
go run ./cmd/spiringo migrate up -env development -config configs
```

启动服务：

```powershell
go run ./cmd/spiringo -env development -config configs
```

查看运行报告：

```bash
curl http://127.0.0.1:8080/system/report.json
```

期望看到：

```json
{
  "modules": [
    {"name": "tenant", "state": "active", "enabled": true},
    {"name": "user", "state": "active", "enabled": true}
  ]
}
```

如果模块没有出现，优先检查：

- 是否调用了 `RegisterModules()`。
- 配置中 `modules.<name>.enabled` 是否为 `false`。
- 依赖模块是否被关闭。
- `Init()` 是否返回错误。
- 数据库迁移是否失败。
